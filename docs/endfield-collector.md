# 엔드필드 공식 공지 수집기 실행 안내

Python 표준 라이브러리만 사용하는 첫 수집기다. 공식 한국어 버전 공지를 HTTPS로 직접 받아 Asia의 이벤트 기간과 확인용 숙제를 JSON으로 만든다. 인게임 계정이나 완료 상태를 읽지 않는다.

## 실행

Python 3.10 이상에서 저장소 최상위 폴더를 기준으로 실행한다. 추가 패키지 설치는 필요 없다.

```console
python -m collector.endfield
```

기본 원문은 [「단청도」 버전 업데이트 설명](https://endfield.gryphline.com/ko-kr/news/9560)이다. 결과는 [data/endfield-asia.candidate.json](../data/endfield-asia.candidate.json)에 저장된다. 기본 명령은 robots.txt와 공식 공지를 실제로 요청한다.

새로운 같은 형식의 공식 공지를 시도하려면 별도 출력 경로를 지정한다.

```console
python -m collector.endfield --url https://endfield.gryphline.com/ko-kr/news/9560 --output data/endfield-asia.candidate.json
```

현재 공지에서 확인한 이벤트 식별자는 [collector/identities.json](../collector/identities.json)에 포함했다. 새 제목이 나타나면 조용히 중복 이벤트를 만들지 않고 실행을 중단한다. 실제 새 이벤트이면 원문을 검토한 후 `--accept-new-events`로 최초 키를 배정한다. 기존 이벤트의 이름 변경이면 해당 기존 항목의 `aliases`에 새 이름을 추가한다. 이 구분을 자동으로 추측하지 않는다.

## 이번 실제 수집 결과

2026-10-23에 공식 HTML을 받아 생성·확인했다.

| 항목 | 결과 |
| --- | --- |
| 대상 구간 | 공지의 신규 이벤트 |
| 이벤트 묶음 | 11개 |
| 세부 일정 | 15개 |
| 양쪽 시각이 명시된 기간 | 6개 |
| 시작 또는 종료 확인이 필요한 기간 | 6개 |
| 확정된 콘텐츠 업데이트 시점 | 3개 |
| 일일 숙제 템플릿 | 4개 |
| 확인 방식 | 개인 완료는 직접 체크 |

참여 일정과 별도로 콘텐츠 업데이트 시점 3개, 교환 마감 1개를 분리했다. 콘텐츠 업데이트는 기간이나 별도 수행 숙제로 해석하지 않는다. 출석 2개와 매일 임무를 명시한 이벤트 2개에서 반복 확인용 템플릿을 생성했다. 구체적인 인게임 임무 목록은 공지에 없으므로 만들어 넣지 않았다.

예를 들어 「위기 대응 준비」는 Asia 10/29 04:00~11/05 04:00을 UTC로 저장하며 한국에서는 10/29 05:00~11/05 05:00으로 표시된다. 「위기 협약 · 잿빛 실험 작전」의 참여 종료는 미확정으로 두고, 교환 마감은 별도 일정으로 저장했다.

## 날짜를 다루는 기준

- Asia의 UTC 오프셋을 공지에서 찾는다. 발견하지 못하면 기본값으로 추정하지 않고 실패한다.
- 기간의 양 끝을 각각 해석한다. “버전 업데이트 후”와 “점검 전”은 NULL로 남긴다.
- 점검의 예정 종료를 실제 이벤트 개방으로 간주하지 않는다.
- Asia와 Americas/Europe 기간이 따로 있으면 Asia만 선택한다.
- 종료가 시작보다 빠르거나 존재하지 않는 날짜이면 출력 파일을 교체하지 않는다.
- 일일 초기화 시각은 이 공지만으로 확정하지 않는다. `resetPolicy=GAME_RESET`은 앱에 저장한 실제 게임 초기화 설정을 사용한다는 뜻이다.

## JSON 상태와 사용 범위

이 결과는 가상 예제가 아닌 실제 공지 추출 결과다. 다만 앱에 무검수 배포되는 운영 피드는 아니다.

```json
{
  "exampleOnly": false,
  "publicationState": "CANDIDATE",
  "autoImportAllowed": false
}
```

`timeState=CONFIRMED`는 기간이면 양끝, 시점이면 `occursAt`이 원문에 명시됐다는 뜻이다. 시간 미확정 기간은 `NEEDS_REVIEW`와 `reviewReasons`로 구분한다. 별도 `collector.publish` 명령은 검수 기록과 공식 원문을 다시 대조한 뒤 앱용 피드를 만든다. [검수 결과·배포 주소·가져오기 계약](endfield-release.md)을 확인한다. 수집 후보를 그대로 앱에 넣지 않는다.

기본 체크 항목은 목표·보상을 사용자가 확인하기 위한 제안이다. 일일 숙제도 `SUGGESTED_FROM_NOTICE`로 표시하고 원문이 일일 임무인지 누적 출석인지 근거 종류를 남긴다. JSON에 `isDone`이나 개인 완료 기록을 넣지 않는다.

## 키와 개정 관리

이벤트 키는 등록부에 한 번 배정한다. 공지 제목의 순서·날짜가 바뀌어도 같은 키를 사용하고, `play`·`stage`·`shop` 키로 세부 일정을 구분한다. 날짜·체크 템플릿 등 의미가 달라지면 해당 일정 개정을 높인다.

같은 내용을 재수집하면 원문 확인 시각은 새로 기록하지만 동일 일정의 개정은 증가시키지 않는다. 원문 또는 생성한 일정 내용이 달라지면 카탈로그 개정을 높인다. 앱은 외부 키를 기존 Room 행과 연결해 개인 기록을 보존해야 한다. 이 수집기는 Room 저장까지 구현하지 않는다.

## 테스트와 재현

```console
python -m unittest discover -s tests -v
```

날짜 변환, 다른 서버 기간 제외, 점검 전 NULL 유지, 단계·상점 분리, 반복 숙제 생성 근거, 제목 순서·기간 변경 시 키 유지, 이름 변경 확인, 오류 시 기존 JSON 보존 등을 테스트한다. 테스트는 합성 HTML을 사용하며 네트워크에 연결하지 않는다.

로컬 진단용 HTML을 남기거나 같은 HTML을 다시 읽을 수 있다. 원문 전체를 저장소에 올리지는 않는다.

```console
python -m collector.endfield --save-html .collector-cache/endfield-9560.html
python -m collector.endfield --html-file .collector-cache/endfield-9560.html
```

## 초기 버전의 제한

- 현재 검증한 형식은 한국어 버전 공지의 **신규 이벤트** 구간이다. 별도의 이벤트·점검 공지, 아래쪽 콘텐츠 업데이트, 헤드헌팅·메일·상시 콘텐츠까지 모두 수집한 결과는 아니다.
- 공지 목록에서 최신 글을 찾아오는 기능과 예약 실행은 아직 없다. URL을 지정해 한 번 수집하는 CLI다.
- 다른 공지에서 같은 이벤트가 재안내될 때의 출처 간 병합은 아직 구현하지 않았다. 현재 등록부는 지정한 공지 안의 이벤트를 추적한다.
- HTML 구조 변경, 새 이름, 여러 개의 기간·상점처럼 검증하지 않은 형식은 실행을 중단하고 확인을 요청한다.
- 네트워크·파싱 실패 시 마지막 정상 JSON을 보존하며, 부분 결과로 덮어쓰지 않는다.
- 현재 수집기에 로그인·쿠키·개인 계정 연동·인게임 자동 완료 기능은 없다.
