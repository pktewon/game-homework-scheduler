# 엔필 검수 결과와 앱 배포 JSON

2026-10-23에 공식 [「단청도」 버전 업데이트 설명](https://endfield.gryphline.com/ko-kr/news/9560)의 **신규 이벤트** 구간을 대조했다. 날짜·서버·반복 숙제 근거와 예외 안내를 AI 보조로 검수했다. 사람이 별도로 승인했거나 공식 운영사가 인증한 데이터라는 의미는 아니다. 공지 전체나 다른 글의 최신 변경까지 포함한 전체 이벤트 목록은 아니다.

## 앱이 받을 주소

- [매니페스트 JSON](https://raw.githubusercontent.com/pktewon/game-homework-scheduler/main/data/manifest.json)
- [배포 JSON 고정 주소](https://raw.githubusercontent.com/pktewon/game-homework-scheduler/main/data/endfield-asia.json)
- [배포 1판 JSON](https://raw.githubusercontent.com/pktewon/game-homework-scheduler/main/data/releases/endfield-asia-v1.json)
- [검수 기록](../reviews/endfield-9560.review.json)

주소는 GitHub 웹 페이지가 아닌 원본 JSON을 반환한다. 앱은 매니페스트에서 프로필이 맞는 항목의 버전별 `url`을 받고, 다운로드한 바이트 수와 SHA-256을 검사한 뒤 적용한다. 버전별 파일을 먼저 저장하고 매니페스트를 마지막에 교체한다. 고정 주소는 수동 확인용으로도 제공한다.

11:59와 12:00은 원문 그대로 구분했다. 초 단위의 추가 보정이나 종료일 다음 날까지의 연장은 하지 않는다.

- **콘텐츠 업데이트** 3건은 추가 임무의 이름·목록이 확인된 것이 아니다. `CONTENT_UPDATE / INSTANT`와 `occursAt`으로 표시하고 체크 항목·일일 숙제를 만들지 않는다. 기존 `stage` 외부 키는 유지했다. 이를 기간으로 취급하면서 생겼던 미확정 종료 2건은 기간 집계에서 제외했다.
- **참여와 교환**은 별개다. 시크릿 생추어리의 종료를 위기 협약 참여 종료로 복사하지 않는다.
- **야생으로**는 참여 조건 충족 시 페이지 종료 후에도 임무와 보상을 진행할 수 있다. 페이지 마감을 스토리·보상 소멸로 알리지 않는다.
- **불꽃으로 맺은 인연**은 기간 제한 운영 임무·보상과 이후에도 가능한 객잔 플레이·이정표 단계 보상을 구분한다.
- **일일 숙제 4개**는 누적 7일 출석 2개와 매일 임무 2개의 확인용 제안이다. 누적을 연속 출석으로 바꾸지 않는다. 개별 임무·개인 진척도·일일 초기화 시각은 이 공지로 확인할 수 없다.

## JSON 계약

| 필드 | 의미 |
| --- | --- |
| `schemaVersion=1`, `releaseSchemaVersion=1` | 후보 공통 형식 및 검수·배포 확장 형식 |
| `publicationState=PUBLISHED`, `autoImportAllowed=true` | 검수한 메타데이터를 가져올 수 있음 |
| `reviewState=SOURCE_REVIEWED` | 원문 대조 완료. 모든 시각이 확정됐다는 뜻은 아님 |
| `timeShape=WINDOW` | 기간. `startAt`, `endAt` 중 불명확한 쪽은 NULL |
| `timeShape=INSTANT` | `occursAt`만 있는 알림. 양쪽 기간 필드는 NULL이며 종료 미확정이 아님 |
| `timeState=NEEDS_REVIEW` | 기간 확인 필요. `reviewReasons`가 미확정 쪽을 표시 |
| `appPolicy` | 카운트다운·알림·체크와 활성화 제한 |
| `sourceKey`, `sourceItemKey`, `sourceTaskKey` | Room 병합용 고정 식별자 |
| `revision`, `catalogRevision`, `releaseRevision` | 일정 변경, 수집 내용 변경, 검수·배포 변경의 개정 번호 |
| `sourceEvidence`, `source`, `review` | 출처·추출 문단·원문 해시·검수 기록 연결 |

일정과 템플릿은 공개 데이터지만 개인 완료 값은 없다. 가져오기를 완료 처리로 간주하지 않는다. 같은 일정에 `SOURCE_REVIEWED`와 `NEEDS_REVIEW`가 공존할 수 있다. 전자는 원문 대조 여부, 후자는 기간의 확실성이다.

## Android 적용 순서

1. HTTPS로 매니페스트를 받는다. 지원 형식과 `endfield-gryphline-asia`를 확인하고 이미 적용한 판보다 낮은 `releaseRevision`은 적용하지 않는다.
2. 버전별 JSON을 받아 바이트 수·SHA-256·형식·프로필·공개 상태·키 중복·기간 순서를 검사한다. 알 수 없는 필수 종류는 거부한다. 실패하면 마지막 정상 Room 데이터를 유지한다.
3. Room 트랜잭션에서 `sourceKey`로 병합한다. 개인 완료·메모·수동 수정은 보존하고 공지 메타데이터를 갱신한다. 체크는 `(sourceKey, sourceItemKey)`, 숙제는 `(sourceKey, sourceTaskKey)`로 연결한다. 노트 변경도 전체 배포 개정에 따라 반영한다. 사라진 항목·옛 체크 기록은 즉시 삭제하지 않는다.
4. 기간 확정 항목만 `startAt <= now < endAt`으로 활성 여부와 종료 임박 순서를 계산한다. 예정 항목은 예정 목록에 둔다. `NEEDS_REVIEW`는 **기간 확인 필요** 영역에 두고 알려진 종료는 표시하되 자동 카운트다운·마감 푸시·활성화를 막는다. 사용자가 실제 시각을 확인하면 로컬 수정값과 근거를 저장한다.
5. 콘텐츠 업데이트는 `occursAt`의 달력 표시로 처리한다. 이벤트 종료로 취급하거나 임의의 수행 숙제를 만들지 않는다. 관련 이벤트 참여 조건은 게임에서 확인한다.
6. 일일 숙제는 기간 확인, 게임 초기화 시각 검증, 사용자 선택 후 회차를 계산한다. `autoCreateRecordsAllowed=false`는 수신만으로 기록을 만들지 말라는 뜻이다. 위 조건 충족 후 앱이 로컬 회차를 만들 수 있으며 완료는 직접 체크한다. 초기화 미확정이면 설정·확인 안내를 보인다.

네트워크 수신·Room 병합·참여 체크와 초기화 설정·일일 회차 체크를 구현했다. API 35 에뮬레이터에서 실제 수신·기록 보존을 확인했다. [현재 구현](android-implementation.md)과 [일일 숙제](daily-tasks.md)를 참고한다. 미확정 기간은 자동 활성화하지 않으며, 사용자가 참여 가능을 직접 확인해 이번 회차 완료만 기록할 수 있다. 공식 NULL은 유지한다. 기간 수동 편집·배경 갱신·새 공지 탐색·예약 수집은 후속 구현이다. `source.checkedAt`을 화면에 표시한다.

## 검수와 재배포

```console
python -m collector.endfield
python -m unittest discover -s tests -v
python -m collector.publish
```

첫 명령은 후보만 생성한다. 원문이나 의미가 달라졌으면 [검수 기록](../reviews/endfield-9560.review.json)을 실제 대조해 갱신해야 마지막 명령이 성공한다. 검수 기록에는 원문 해시·후보 지문·전체 일정 내용 해시와 독립적으로 대조한 UTC 시각·일일 숙제 근거가 있다. 지문만 새 값으로 바꿔 승인하는 절차가 아니다. 기본 배포 명령은 공식 원문을 다시 받아 재생성한 내용과 검수 기록을 모두 비교한다.

```console
python -m collector.publish --html-file .collector-cache/endfield-9560.html
```

위 명령은 저장한 공식 HTML로 오프라인 재현할 때 사용한다. 원문이 최신이라는 추가 확인을 대신하지 않는다. 네트워크·검수 불일치 시 기존 매니페스트를 보존한다. 같은 검수 내용은 같은 배포판을 유지하며, 검수 메모를 포함한 의미가 바뀌면 새 판을 만든다. 기존 버전별 JSON을 다른 내용으로 덮어쓰는 것은 거부한다. 변경 후보·검수 기록·배포 JSON·매니페스트는 함께 커밋한다. 자동 GitHub 업로드·예약 수집은 CLI에 포함하지 않았다.

27개 테스트로 시각·서버 처리, NULL 유지, 콘텐츠 시점 분리, 검수 누락·원문 변경·변조 거부, 개인 완료 제외, 재배포 동일성, 해시·바이트 수, 실패 시 기존 매니페스트 보존을 확인했다.
